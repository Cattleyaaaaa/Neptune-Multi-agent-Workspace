## 项目定性分析（回答"这是 agent 吗 / 什么类型"）

通读 `packages/general_agent/*`、`apps/api/*`、README 与 docs/architecture.md，给出定性结论（无代码改动）：

- 定性：**不是单个 agent，而是 Supervisor 驱动的多 Agent 系统**，并以"带 Web 工作台的 Agent 应用/平台"形态交付。
- 判定依据：
  - `graph.py` 用 LangGraph `StateGraph` 固定节点 + 条件边（`route` 按 `next_agent` 分支），属**预定义图编排**，不是自由 ReAct 循环。
  - `capabilities.py` 的 `CapabilityRegistry.plan_for` 按 `task_type` 从能力注册表选角组队；`agents.py` 的 `GeneralSupervisorAgent.dispatch` 只做派发/完成判断/停止条件。
  - 半自主 + human-in-the-loop：`graph.py` 的 `approval_gate` 用 `interrupt` 暂停，停止条件为 `max_steps` / `asyncio.timeout`。
- **关键诚实点（以后别误述）**：`settings.py` 默认 `reasoning_provider="local"`，`LocalStructuredReasoner` 是确定性模板推理，**默认配置下不调 LLM**；LLM 只是可插拔 provider（OpenAI Responses + `FallbackReasoner`）。`prepare_external_action` 是模拟回执，不真写外部系统；MCP 探测到的工具未接入运行时工具注册表。
- 谱系落点：多 Agent 系统（内核） + Agent 平台（外壳），横跨"多 Agent"与"平台"两格。

## 可复用经验
- 回答"某项目是什么类型的 agent"时，判定顺序：控制流形态（图/循环）→ 角色结构（单/多、有无 supervisor）→ 自主度（是否 HITL、停止条件）→ 推理后端是否真接 LLM → 交付形态（库/应用/平台）。最后一项最容易被忽略。
